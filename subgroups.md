The idea is that each subgroup has a named lead who is neither the Maria nor Emma. We each sit in one primary subgroup. This does not mean we cannot also contribute within other sub-groups, but this attempts to split the work fairly across discipline/strengths of team members. We can edit these groups and their remit when we are together, this below is so we have somewhere to start from:

## A — Data ingestion and harmonisation, shared code components

**Focus:** input data sources, metadata standards, controlled vocabularies, licensing of shared data, the core library, containerisation, versioning, and code review.

**Supported by:** LWE software engineers, Emma + ...

## B — Forecast workflow, validation & evaluation

**Focus:** forecasting, forecast skill (evaluation), iteration

**Supported by:** Maria + ...

## C — Infrastructure and deployment

**Focus:** where it runs, CI/CD, scheduling, storage, authentication, and long-term hosting after the project ends.

**Supported by:** LWE software engineers, Emma + ...

## D — Users, uptake and dissemination

**Focus:** who actually uses the forecasts, co-design for and with stakeholders, papers, policy briefs, training materials, and the sustainability plan to futureproof beyond the PREDICT project.

**Supported by:** Melina + ...

## Across all groups

Open science and FAIR compliance, funder reporting. Likely Maria :)
